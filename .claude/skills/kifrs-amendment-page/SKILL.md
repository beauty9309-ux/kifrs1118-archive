# A 개정 상세 페이지 생성 (실질 개정 소수만)

## 언제 쓰나 / 쓰지 않나
- **쓴다:** 영향도가 '중간/높음'인 실질 개정(표시·측정·공시 로직 변경). 남은 후보: 제1008호 재무제표의 작성 기준, 제1033호 주당이익, 제1034호 중간재무보고, 제1101호 최초채택. (제1007호는 완료)
- **쓰지 않는다:** 용어(IFRSs→IFRS Accounting Standards)·참조(제1001호→제1118호)·명칭 정비 등 경미 개정. → 별도 페이지 대신 `kifrs-amendment-map`의 표에 한 행으로 둔다.

## 소스
- **1차: `sources/1118-consequential-amendments.txt`** 에서 해당 기준서 섹션(예: "기업회계기준서 제1007호")을 찾는다. (기준서 원문을 하나씩 뒤지지 말 것 — 이 문서가 전체 신구대조본)
- **보조(선택): `sources/standards/`** 의 해당 기준서 원문 PDF — 바뀐 문단의 맥락 확인용.
- 소스가 없으면 먼저 요청한다. 내용을 기억으로 추측하지 않는다.

## 절차
1. 마스터에서 해당 기준서 섹션을 찾고, 섹션 끝의 **개정 근거 문단**(예: 제1007호는 문단 64)에서 바뀐 문단 번호를 **개정·신설·삭제로 나눠** 전부 뽑는다. 이 문단 번호를 출처로 기록.
2. 아래 **신구대조 읽는 법**으로 문단을 하나씩 대조한다.
3. 문단별로 **확정 / 대조본 확인 필요**를 나눈다. 불분명하면 지어내지 않는다.
4. 영향도(중간/높음) 판정.
5. `amendments/k1115.html` 복제 → 본문만 교체(`/shared.css` 링크 유지).
6. `node check-copyright.js <파일>` 통과 + 모바일·링크 확인.
7. 개정 지도 행 링크 + 홈 피드 1줄 (아래 **마무리 연결** 참조).

## 신구대조 읽는 법 (마스터 해독)
추출 과정에서 서식(취소선 등)이 사라져 있다. 네 가지 패턴으로 판정한다.

| 패턴 | 생김새 (실례) | 판정 |
|---|---|---|
| **병기** — 신·구 문구가 붙어서 나온다 | `영업당기순손익` = 신 '영업손익' / 구 '당기순손익'<br>`표시공시한다` = 신 '표시' / 구 '공시'<br>`제11181001호` = 신 1118호 / 구 1001호 | 확정 |
| **삭제** — `[국제회계기준위원회에 의하여 삭제됨]` **뒤에 구 본문이 그대로 남아 있다** | 문단 33·34 (이자·배당 분류 선택권) | 확정 — 없어진 옛 규정을 여기서 읽는다 |
| **신설** — 병기 없이 단독 등장 | 33A, 34A~34D | 확정 |
| **패턴 없음** — 근거 문단이 지목했는데 위 셋 어디에도 안 걸림 | 문단 12, 47 | **대조본 확인 필요** |

### ⚠ 병기 순서로 신·구를 판단하지 마라
`앞=신 / 뒤=구`는 **성립하지 않는다.** 취소선 서식이 추출에서 사라져 순서가 뒤섞인다. 실제로 두 방향이 다 나온다.
- 제1007호 문단 46: `제1008호 '재무제표의 작성 기준'제1001호 '재무제표 표시'` → 신이 앞
- 제1033호 문단 13: `제1001호제1118호` → 신이 **뒤**

**의미로 판정한다** (이건 항상 성립):
- **신** = 제1118호, 제1008호 `'재무제표의 작성 기준'`, 1118호가 새로 만든 용어(영업 범주·중간합계·MPM·손익계산서)
- **구** = 제1001호 `'재무제표 표시'`, 제1008호 `'회계정책, 회계추정치 변경과 오류'`, `별개의 보고서`
- 1118호가 1001호를 **대체**했으므로 1001호가 새 문구일 수는 없다. 이 사실 하나로 방향이 결정된다.

- 구 본문이 문단 끝에 **번호 없는 고아 줄**로 떨어져 나오는 경우가 있다(제1007호 문단 18의 구 ⑵, 제1008호 문단 1의 구 목적 조항). 문단 번호 없이 이어지는 줄을 그냥 넘기지 말 것.
- '확인 필요' 문단은 숨기지 말고 페이지에 **`확인이 더 필요한 문단`** 섹션(`.grounds`)으로 드러낸다. 무엇을 모르는지 밝히는 게 이 아카이브의 신뢰도다.

## 저작권 — 자가검사에서 실제로 걸리는 지점
- **개정 근거 문단 요약이 거의 항상 걸린다.** 원문이 "…를 개정하였고 …를 추가하였으며 …를 삭제하였다" 구조여서, 그 문장 구조를 따라 쓰면 130자 + 한다체 2회로 `check-copyright.js`에 잡힌다.
- 문장을 버리고 **목록형**으로 쓴다:
  `개정 13개 — 6·10·12·14·… / 신설 5개 — 33A·34A~34D / 삭제 2개 — 33·34. 적용 시점은 1118호와 같습니다.`
- **`--no-verify`로 우회하지 않는다.** 훅이 잡았다는 건 원문에 너무 붙었다는 신호이므로 다시 쓴다.
- 번호 문단 본문은 요지만 인용(원문은 회계기준원 링크). BC·적용사례·소수의견은 **요약만**.

## 템플릿·스타일 메모
- 기준 파일 실제 경로는 **`amendments/k1115.html`**, 출력은 **`amendments/k[번호].html`**.
- 영향도 배너는 3단계 톤이 다 있다. `.scale`의 `.on`을 해당 등급에 붙이는 것도 잊지 말 것.
  - 낮음 → `<div class="impact">` (초록) · 중간 → `<div class="impact mid">` (슬레이트) · 높음 → `<div class="impact high">` (앰버)
- **영향도는 등급을 아끼지 말고 구분해서 쓴다.** 실질 개정이라도 영향 범위가 특정 기업군에 한정되면 중간이 맞다(제1033호 = 추가 주당금액을 공시하는 기업만). 기준서 전체가 재편되거나 전 기업의 표·정책이 바뀌면 높음(제1007호·제1008호).
- **기준 파일에는 BreadcrumbList JSON-LD가 빠져 있다** → 새 페이지에는 `Article` + `BreadcrumbList` 둘 다 직접 넣는다.
- 변경 덩어리가 여러 개면 `.diff` 블록을 주제별로 나눠 쓰고, 블록마다 아래에 짧은 해설 문단을 붙인다.

## 페이지 구조 (순서 고정)
헤더+breadcrumb → eyebrow+H1+dek(결론 먼저)+출처 → 개정 영향도 배너 → 무엇이 바뀌었나(변경 전→후) → **확인이 더 필요한 문단**(있을 때만) → 왜 바뀌었나(1118호와의 연결) → 실무 시사점 → 시행(2027.1.1 이후 최초 회계연도, 조기적용 가능) → 근거 문단 → 출처·저작권·면책.

## 마무리 연결 (넷 다 해야 완료다)
- [ ] **개정 지도** `amendments/index.html`의 해당 행:
  `<td class="link soon">상세 예정</td>` → `<td class="link"><a href="/amendments/kXXXX">상세 →</a></td>`
- [ ] **홈 피드**에 1줄 추가하고, **같은 주제의 '예정' placeholder 행이 남아 있으면 지우거나 다음 대상으로 교체**한다(같은 항목이 두 번 노출되는 것을 막는다). 다음 대상이 없으면 placeholder 행 자체를 없앤다.
- [ ] **`sitemap.xml` 에 `<url>` 블록 추가** — 자동 생성이 아니다. 빠뜨리면 새 페이지가 색인되지 않는다.
- [ ] **`node build-search-index.js` 재실행** — 사이트 검색 색인도 수동 생성이다. 빠뜨리면 새 글이 검색에 안 잡히는데 에러가 안 뜬다.
  ```xml
  <url>
    <loc>https://kifrs1118-archive.vercel.app/amendments/kXXXX</loc>
    <lastmod>YYYY-MM-DD</lastmod>
  </url>
  ```
- [ ] 판정이 B축 쟁점이나 다른 개정 상세와 이어지면 **상호링크**한다(예: 1007호 34B의 '주된 사업활동' → `/issues/customer-financing-interest`, MPM → `/amendments/k1033`↔`/amendments/k1034`).

## SEO
- `canonical`·`og:url` 도메인은 **`https://kifrs1118-archive.vercel.app`** 를 쓴다. placeholder를 남기지 않는다 — 잘못된 canonical은 사이트 전체를 색인에서 밀어낸다.
