# K-IFRS 제1118호 쟁점 아카이브

한국회계기준원 공개자료를 근거로 **K-IFRS 제1118호 '재무제표 표시와 공시'(IFRS 18)** 를 정리하는 비영리 학습용 아카이브입니다.

**→ [kifrs1118-archive.vercel.app](https://kifrs1118-archive.vercel.app)**

빽빽한 신구대조표와 TF 논의록을, 회계사·감사인·회계 실무자·CPA 수험생이 몇 분 안에 읽을 수 있는 형태로 옮깁니다.

---

## 다루는 범위

제1118호 **하나만** 다룹니다. 종합 회계자료 데이터베이스가 아닙니다.

내용은 두 축으로 나뉩니다.

### A · 개정 지도 — `/amendments`

1118호는 다른 기준서 38개를 함께 개정했습니다. 그중 대부분은 참조·명칭 정비이고 **실질 변화는 5건에 집중**돼 있습니다.

38개를 38개 페이지로 쪼개지 않았습니다. 영향도 표 한 장으로 요약하고, 실질 개정 5건(제1007·1008·1033·1034·1101호)만 상세 페이지를 둡니다. 무엇을 안심하고 넘겨도 되는지 가리는 것이 이 축의 값입니다.

### B · 쟁점 해설 — `/issues`

기준서를 읽어도 결론이 나지 않는 실무 쟁점을 **갑설·을설·결론**으로 정리합니다. 정착지원 TF에서 위원들이 실제로 무엇을 두고 갈렸는지, 어느 문단의 관계에서 결론이 나뉘었는지를 풀어씁니다.

결론이 확정되지 않은 쟁점은 그렇게 적습니다.

| 표기 | 뜻 |
|---|---|
| (없음) | 다수의견으로 정리됨 |
| **잠정** | 다수의견은 있으나 후속 논의가 예정됨 |
| **유보** | 다수의견 자체가 형성되지 않음 |

쟁점 13건을 가로질러 **반복해서 갈리는 지점**을 정리한 [횡단 정리](https://kifrs1118-archive.vercel.app/issues/faultlines) 페이지도 있습니다.

## 지키는 원칙

- **기준서 문단은 번호와 요지만.** 문단 전문을 복제하지 않습니다. 원문은 모두 회계기준원 링크로 연결하고, 요지는 작성자의 표현으로 다시 씁니다.
- **근거는 회계기준원 공개자료만.** 정착지원 TF 논의내용·개정 자료·질의회신·교육자료를 씁니다. 회계법인 발간자료는 본문에 재수록하지 않습니다.
- **모르는 것은 모른다고 씁니다.** 자료만으로 특정할 수 없으면 '확인 필요'로 남기고 추측하지 않습니다.
- **비영리.** 광고나 유료 요소를 두지 않습니다.

배포된 20개 콘텐츠 페이지는 **전부 원문과 한 줄씩 대조 검증**을 마쳤습니다. 검증 기록은 [`NEXT-SESSION.md`](NEXT-SESSION.md)에, 그 과정에서 배운 것은 [`RETROSPECTIVE.md`](RETROSPECTIVE.md)에 있습니다.

> 이 사이트의 해설은 한국회계기준원의 공식 해석이 아니며, 구체적 사안에 대한 회계·감사·법률 자문이 아닙니다. 실제 적용 시 원문과 전문가 판단을 따르세요.

## 구조

정적 HTML입니다. 프레임워크도 빌드 단계도 없습니다.

```
kifrs1118-home.html      홈 (단 하나뿐이라 CSS를 인라인으로 둠)
shared.css               콘텐츠 페이지 공용 스타일 — 디자인 토큰·컴포넌트
issues/                  B 쟁점 해설 + 인덱스
amendments/              A 개정 상세 + 개정 지도(= 인덱스 겸용)
about.html               소개·저작권·작성자
search.js                브라우저 검색 (색인 JSON 하나만 받아 씀)
build-search-index.js    검색 색인 생성 스크립트
check-copyright.js       저작권 자가검사 (pre-commit 훅에서 실행)
sitemap.xml robots.txt vercel.json
```

**검색**은 서버 없이 동작합니다. `build-search-index.js`가 각 페이지에서 제목·요약·본문과 **인용된 기준서 문단번호**를 뽑아 `search-index.json`을 만들고, 브라우저가 그 파일 하나를 받아 찾습니다. 첫 입력 때만 내려받습니다.

문단번호가 색인에 들어 있어 `B40`이나 `53⑶` 같은 검색이 됩니다 — 그 문단으로 결론이 갈린 쟁점들이 바로 나옵니다.

## 로컬에서 보기

루트 절대경로(`/shared.css`)를 쓰므로 파일을 직접 열면 스타일이 깨집니다. 간단한 서버를 띄우세요.

```bash
python -m http.server 8765
# http://127.0.0.1:8765/kifrs1118-home.html
```

배포본은 `vercel.json`의 `cleanUrls`로 `/about`처럼 확장자 없이 열리지만, 로컬 간이 서버에서는 `.html`을 붙여야 합니다.

## 페이지를 추가할 때

**손대야 하는 곳이 넷이고, 넷 다 자동이 아닙니다.** 빠뜨려도 에러가 나지 않아 알아채기 어렵습니다.

1. 홈 `kifrs1118-home.html`의 최근 업데이트 피드에 한 줄
2. `issues/index.html`(쟁점) 또는 `amendments/index.html`(개정 지도)에 한 줄
3. `sitemap.xml`에 `<url>` 블록
4. `node build-search-index.js` 재실행

그리고 커밋 전에 저작권 자가검사를 통과해야 합니다.

```bash
node check-copyright.js <파일>
```

기준서 원문은 한다체 규범문이고 해설은 합니다체라는 문체 차이로 전문 복제를 탐지합니다. pre-commit 훅에서도 자동 실행됩니다.

```bash
git config core.hooksPath .githooks
```

자세한 규칙은 [`CLAUDE.md`](CLAUDE.md)에 있습니다.
